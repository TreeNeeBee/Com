## Overview

LightAP Com is an **AUTOSAR AP R25-11** compliant communication module with a **zero-daemon, plugin-based architecture**.

### Key Features

- **Zero-Daemon Service Discovery** — No RouDi, no background processes. Fixed slot mapping with seqlock O(1) lookup (<500ns)
- **Plugin-Based Bindings** — `ITransportBinding` NVI interface, priority-based auto-selection, YAML-driven configuration
- **Split Code Generation** — `lap-sidl-gen` generates isolated `gen_server/` and `gen_client/` from Franca FIDL
- **Dual-Layer IDL** — Franca IDL → ara::com API + DDS IDL (auto-generated by `fastddsgen`)

### Binding Status

| Binding | Priority | Latency | Throughput | Status | Use Case |
|---------|----------|---------|------------|--------|----------|
| **CoreIPC** | 100 | < 1µs | > 10 GB/s | ✅ Production | Intra-ECU, zero-copy SHM |
| **DDS** | 80 | < 10µs SHM / < 30µs UDP | > 1 GB/s | ✅ Production | Cross-ECU, QoS, discovery |
| SOME/IP | 60 | — | — | ⚠️ Planned | AUTOSAR CP interop |
| Socket | 40 | — | — | ⚠️ Planned | Lightweight IPC, legacy |

## Architecture

```
┌─────────────────────────────────────────────────┐
│           Application Layer                     │
│   (ara::com API — Proxy / Skeleton / Runtime)   │
├─────────────────────────────────────────────────┤
│           Binding Manager                       │
│   (Priority selection, YAML config, dlopen)     │
├──────────────────┬──────────────────────────────┤
│  CoreIPC ✅      │  DDS (Fast-DDS 3.x) ✅      │
│  Zero-copy SHM   │  SHM + UDP, Discovery Server│
│  < 1µs, > 10GB/s │  < 10µs SHM / < 30µs UDP   │
├──────────────────┼──────────────────────────────┤
│  SOME/IP ⚠️     │  Socket ⚠️  │  D-Bus ⚠️    │
│  (skeleton)      │  (skeleton)  │  (skeleton)   │
└──────────────────┴─────────────┴────────────────┘
```

### Core Mechanisms

- **Fixed Slot Mapping**: `slot = service_id & 0x03FF` — 1024 slots, zero hash collisions
- **Dual Registry**: QM+AB (0666) + ASIL-CD (0640) — functional safety physical isolation
- **seqlock Concurrency**: Lock-free read (<100ns), atomic write
- **Heartbeat**: 100ms interval service liveness detection

For detailed architecture, see [docs/architecture/ARCHITECTURE_SUMMARY.md](docs/architecture/ARCHITECTURE_SUMMARY.md).

## Transport Bindings

### CoreIPC ✅

Zero-daemon, zero-copy shared memory IPC for intra-ECU communication.

- < 1µs latency (64B), < 10µs (1MB)
- \> 10 GB/s throughput
- No external dependencies

### DDS ✅

eProsima Fast-DDS 3.x integration for cross-ECU distributed communication.

- < 10µs SHM (same host), < 30µs UDP (cross-host)
- \> 1 GB/s throughput
- Discovery Server support, QoS Reliability/Durability

### SOME/IP / Socket / D-Bus ⚠️ Planned

Skeleton files exist in `source/binding/{someip,socket,dbus}/`. Core logic not yet implemented.

## Quick Start

### Prerequisites

```bash
# Ubuntu 22.04+
sudo apt install build-essential cmake \
    libboost-all-dev nlohmann-json3-dev libyaml-cpp-dev

# For DDS binding
sudo apt install libfastdds-dev fastddsgen
```

### Build

```bash
git clone https://github.com/nicx-next/LightAP.git
cd LightAP
mkdir build && cd build
cmake .. -DENABLE_BUILD_TESTS=ON -DENABLE_BUILD_EXAMPLES=ON
cmake --build . -j$(nproc)
ctest --verbose
```

## Code Generator

`lap-sidl-gen` generates server and client code from Franca FIDL definitions using **split generation** (isolated `gen_server/` and `gen_client/` directories).

```bash
# Generate server code
lap-sidl-gen -i MyService.fidl -o gen_server --server

# Generate client code
lap-sidl-gen -i MyService.fidl -o gen_client --client

# Generate both + specify binding
lap-sidl-gen -i MyService.fidl -o gen_server --server --binding coreipc,dds
lap-sidl-gen -i MyService.fidl -o gen_client --client --binding coreipc,dds
```

For generator architecture, see [docs/architecture/GENERATOR.md](docs/architecture/GENERATOR.md).
